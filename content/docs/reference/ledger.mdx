## Ledger.New

```luau
Ledger.New<D>(Options: Config<D>) -> Store<D>
```

Builds a store. Throws on anything wrong with the options, at build time, rather than letting it
misbehave later.

| Option | Type | |
| --- | --- | --- |
| `Name` | `string` | Required. The datastore name, 1 to 47 characters. |
| `Reducer` | `(State, Op) -> State?` | Required. See [Writing a reducer](/docs/concepts/reducer). |
| `Default` | `D` | Required. The fresh state table. |
| `Balance` | `string?` | Names a number field for [transfers](/docs/guides/transfers). |
| `Migrations` | `{ Migration }?` | See [Migrations](/docs/guides/migrations). |
| `Keys` | `"Player" \| "String"` | Defaults to `"Player"`. |
| `OnLoadFailed` | `((Player, Reason) -> boolean)?` | What to do when a load fails. See below. |

The name caps at 47 rather than the datastore's 50 because Ledger also creates `<Name>_Tx` for
transaction markers.

`Default` can't declare any key starting with `_`, and it has to be storable, so JSON only.

Two stores can't share a name in one server. Call `Store:Destroy()` first if you need to rebuild
one.

### OnLoadFailed

By default a load that fails kicks the player with "Your data failed to load, please rejoin". That's
the right thing most of the time, but it treats every failure the same, and they aren't the same.
`OnLoadFailed` is handed the player and the [reason](/docs/concepts/reasons), and returns whether it
dealt with them. Return `true` and Ledger leaves them alone. Return `false` and it kicks as usual.

```luau
local Store = Ledger.New({
	Name = "PlayerData",
	Reducer = Reducer,
	Default = { Gold = 0 },
	OnLoadFailed = function(Player: Player, Why: Ledger.Reason): boolean
		if Why == Ledger.Reason.Behind then
			-- this server is running an old build, send them to one that isn't
			TeleportService:Teleport(game.PlaceId, Player)
			return true
		end
		return false
	end
})
```

`Behind` means the record was written by a newer build than this server is running, so a rejoin lands
them on the same old server and fails again. `Unresolved` is usually the datastore having a bad
minute, where a rejoin is exactly right.

It's a callback rather than an [Observer](/docs/reference/observer) because it has to answer, and an
observer can't. It's allowed to yield, which is what makes a teleport possible, and anything sitting
in `WaitForLoaded` is let go before it's called rather than after.

If it throws, Ledger warns and kicks, same as if it had returned `false`. If it says `true` and the
player is still sitting in the server with no data, you get a warning, since that's almost always a
mistake.

Only for `Keys = "Player"` stores, since `Store:Load` is what calls it. Passing it on a
`Keys = "String"` store throws at build time.

## Ledger.UseMock

```luau
Ledger.UseMock(Options: { Players: number?, Throttled: boolean? }?) -> Service
```

Points every store built after this call at an in memory datastore. `Players` sizes the request
budget, `Throttled` defaults to true. See [Testing](/docs/guides/testing).

## Ledger.UseReal

```luau
Ledger.UseReal() -> ()
```

Back to the real `DataStoreService`. Only affects stores built after the call.

## Ledger.UseClock

```luau
Ledger.UseClock(Reads: (() -> number)?) -> ()
```

Swaps the function Ledger reads the time from. Pass `nil` to go back to `os.time`.

## Ledger.Sweep

```luau
Ledger.Sweep() -> ()
```

Forces a background maintenance pass right now: finish stranded transfers, settle stuck transaction
legs, tidy up old markers. The sweeper does this on its own, so this is for tests and incidents.

## Ledger.CloseAll

```luau
Ledger.CloseAll() -> ()
```

Shuts everything down. Stops the sweeper, tells every queue to skip ahead to the last write, saves
every live session, and yields until it's all done.

Put this in `BindToClose` and nothing else.

```luau
game:BindToClose(function()
	Ledger.CloseAll()
end)
```
